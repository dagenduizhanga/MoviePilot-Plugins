# Oyunfor 礼品卡购买

适用于 **MoviePilot V2** 的插件：在 [oyunfor.com](https://www.oyunfor.com) 自动购买 **App Store & iTunes 礼品卡（土耳其区，TL 面额）**，
取回兑换码后推送给你。

**推荐用法（币安支付）**：你发 `/oyunfor_buy 250`，插件下单并把 **币安付款链接 + 二维码** 推给你；你在币安 App 里付款；
插件检测到付款后，把 **兑换码** 推给你。插件不保存任何付款信息。

另外也支持用账户余额付款，或用银行卡付款（需要 3D Secure 验证时，插件会把验证请求转给你）。

## ⚠️ 先读这一段

1. **这个插件没有在真实的 oyunfor.com 上跑过。** 开发环境访问 oyunfor.com 会被 Cloudflare 拦下，所以页面结构是按土耳其电商的常见写法推断的。
   所有步骤都用「多候选文字/属性匹配」来定位按钮和输入框，并且每一步都会截图、保存网页。插件已经在本地模拟站点上跑通了全部流程，
   但第一次对接真实站点，很可能有一两步要按截图调整。
   - 正因为这样，**「演练模式」默认开启**：插件只走到付款前一步，不会扣款。
2. **推荐用币安支付（默认）**，其次是余额付款。这两种方式插件都不碰你的付款信息：
   - 币安支付：插件只负责把付款码转给你，付不付款由你在币安 App 里决定；
   - 余额付款：你自己先给 Oyunfor 账户充值，插件只用余额下单。
3. **币安支付**要注意：
   - 需要币安账户完成 KYC，并开通 Binance Pay。USDT 要放在 **资金账户（Funding）**，不是现货账户。网上教程提到这个选项有时不显示，具体以结算页为准。
   - 有用户说 Oyunfor 对币安支付收约 2.5% 的手续费，这个说法没有核实。币安页面上显示的 USDT 金额就是实付金额。
   - **新加坡用户特别注意**：2021 年 MAS 把 Binance 列入投资者警示名单后，币安对新加坡用户限制了多项服务（法币入金、现货交易、付款等）。
     你的币安账户如果是按新加坡居民做的 KYC，Binance Pay 可能用不了。请先在币安 App 里确认能用 Pay 付款，再用这个模式。
4. **银行卡模式**能用，但要注意：
   - Oyunfor 的用户协议说他们不保存卡信息。如果网站上没有「已保存的卡」，插件只能把卡号、有效期、CVV **明文**存进 MoviePilot 数据库，每次自己填。
     你的 MoviePilot 数据库或备份一旦泄露，这张卡也就泄露了。可以的话，用一张限额低的虚拟卡。
   - 新加坡的银行（DBS、UOB 等）现在大多把网上刷卡的 3DS 改成了 **在银行 App 里确认（Digital Token）**，不再发短信验证码。
     插件两种都支持：要验证码就回复验证码，要在 App 里确认就去 App 点确认，页面会自动继续。
   - 土耳其的支付网关可能拒绝外国卡。请先在浏览器里手动买一次，确认你的卡能用。
5. 这些卡**只能在土耳其区的 Apple 账户**兑换。苹果要求账户国家和你的居住地、付款方式一致，跨区使用有被限制的风险，需要你自己评估。

## 工作流程

```
打开首页（复用登录状态 / Cookie，必要时用账号密码登录）
  → 读余额 → 清空购物车 → 找到面额对应的商品页（核对面额、价格、库存）
  → Hemen Al / Sepete Ekle → 购物车 → 结算页
  → 选付款方式（币安 / 余额 / 银行卡）→ 勾选销售协议 → 核对应付金额（不能超过单笔上限）
  → [演练模式到这里停下：不会创建付款单]
  → 币安：创建付款单 → 把付款链接、二维码、USDT 金额、倒计时推给你 → 你在币安 App 付款
          → 页面跳到成功页，或在订单页查到新兑换码（每 90 秒查一次；你点「我已付款」后改为每 20 秒）
  → 银行卡：付款 → 如需 3DS，推给你，等你回复验证码或在 App 里确认
  → 结果页 / 订单详情里取出兑换码（App Store 码是 X 开头的 16 位）→ 推送给你
```

## 安装

插件市场里添加仓库 `https://github.com/dagenduizhanga/MoviePilot-Plugins`，然后安装 **Oyunfor 礼品卡购买**。
插件不需要额外的 Python 依赖，浏览器用的是 MoviePilot 自带的 CloakBrowser / Playwright。

## 第一次使用

1. 在电脑浏览器里登录 oyunfor.com。按 F12 打开开发者工具 → 网络 → 刷新页面 → 点开任意一个请求，把请求头里的 `Cookie` 整段复制，粘贴到插件设置里。
2. 填好面额（例如 `250`）和付款方式，**保持「演练模式」开启**，打开「立即购买一次」，然后保存。
3. 一分钟左右后打开插件详情页，看结果和最近一次截图。
   - 结果是「演练完成」，且应付金额正确：说明前面每一步都对上了。
   - 结果是「失败」：看说明文字和截图。也可以把诊断包发给帮你调试的人（见下面「诊断文件」）。
4. 演练通过后，**关闭演练模式**，再买一次最小面额，确认付款和取码都没问题。

## 币安支付怎么操作

插件会发一条「请用币安付款」的消息，里面有：

- 应付的 USDT 金额和页面上的倒计时；
- **付款链接**：手机上点开会跳到币安 App。Telegram 里还有一个「🔗 打开币安付款」按钮；
- **二维码图片**：在币安 App 里用「扫一扫」扫码。也可以长按保存图片，再从相册识别。插件详情页上也会显示这个二维码。

付款后不需要回复，插件会自动取码。如果几分钟都没动静，点「✅ 我已付款」或发 `/oyunfor_paid`，插件会马上去订单页查。

| 情况 | 结果 |
| --- | --- |
| 付款后 Oyunfor 发货 | 推送兑换码 |
| 等待时间到了还没付款（默认 15 分钟） | 记为「验证超时」，不计入每日次数。**之后不要再扫这个码** |
| 你说已付款，但时间到了还没查到兑换码 | 记为「结果未知」，提醒你去订单页核对 |
| 取消（`/oyunfor_cancel` 或按钮） | 不再等待；不付款的话，币安付款单到期会自动关闭 |

插件关掉浏览器之后，只要你付了款，Oyunfor 仍会发货，兑换码会出现在网站的「Siparişlerim」里。

> 二维码图片的取法：插件在 MoviePilot 本机提供一个带一次性令牌的地址（`/api/v1/plugin/OyunforGiftCard/qr?token=…`），
> MoviePilot 取到图片后再发给 Telegram 等渠道。任务结束后，令牌就失效了。
> 有些消息渠道（如企业微信）只转发图片地址、自己不取图，可能显示不出二维码，这时用消息里的付款链接即可。

## 3D Secure 验证怎么操作（银行卡模式）

插件停在银行验证页时，会给你发一条「需要你验证付款」的消息。下面几种方式任选一种：

| 方式 | 做法 |
| --- | --- |
| 聊天命令 | `/oyunfor_code 123456`（短信或 OTP 验证码） |
| 银行 App 确认 | 在银行 App 里点确认，页面会自动继续；也可以点消息里的「✅ 已在银行App确认」按钮，或发 `/oyunfor_code`（不带参数） |
| 网页 | 插件设置 →「验证码（网页提交）」里填验证码，点保存 |
| HTTP 接口 | `GET /api/v1/plugin/OyunforGiftCard/code?code=123456&apikey=你的APIKEY`（可以接 iOS 快捷指令） |
| 取消 | `/oyunfor_cancel`，或点消息里的「❌ 取消购买」 |

默认等 5 分钟，超时就放弃这笔交易。**放弃之后，不要再在银行 App 里确认它。**

> 插件的消息类型是「插件」。如果你在 MoviePilot 的通知设置里关掉了这个类型，就收不到验证提醒。

## 远程命令

| 命令 | 说明 |
| --- | --- |
| `/oyunfor_buy` | 按设置里的面额和数量购买 |
| `/oyunfor_buy 250 2` | 买 2 张 250 TL |
| `/oyunfor_buy 100 dry` | 演练一次（不扣款），不管设置里有没有开演练模式 |
| `/oyunfor_buy https://www.oyunfor.com/... 1` | 按商品链接购买 |
| `/oyunfor_paid` | 告诉插件「我已经用币安付款了」，插件会马上去订单页确认 |
| `/oyunfor_code 123456` | 提交 3DS 验证码；不带参数表示「已在 App 里确认」 |
| `/oyunfor_cancel` | 取消正在进行的购买 |
| `/oyunfor_status` | 检查登录状态和余额 |

用命令触发的任务，结果会直接回复给发命令的人。

## 配置说明

| 配置 | 说明 |
| --- | --- |
| 演练模式 | 默认开启。币安和余额模式停在付款按钮前（不会生成付款单）；银行卡模式会进入支付页，但不填卡、不提交 |
| 立即购买一次 | 保存后马上按当前设置执行一次 |
| Oyunfor Cookie | 推荐。插件会把浏览器的登录状态保存下来，之后优先沿用；你更换 Cookie 后会丢弃旧的登录状态 |
| 账号 / 密码 | 可选。只在页面显示未登录时尝试登录；登录要短信验证码时，同样转发给你。有图形验证码时无法自动登录 |
| 面额 / 数量 / 商品链接 | 按面额在 App Store 分类页找商品；填了商品链接就直接用链接。插件会核对商品页标题上的面额，对不上就停下 |
| 付款方式 | 币安支付（默认，推荐）/ 账户余额 / 银行卡 |
| 币安付款等待 | 推送付款码后最多等多少分钟，默认 15 |
| 使用网站已保存的卡 / 后 4 位 | 网站有已保存的卡时选它（用后 4 位挑选） |
| 卡号 / 持卡人 / 有效期 / CVV | 只在网站没有已保存的卡时使用，明文保存 |
| 单笔金额上限 | 默认 2000 TL。商品价格或结算页的应付金额超过它就停下；两者都识别不出来时也会停下 |
| 每日最多下单次数 | 默认 3 次，演练不计入 |
| 验证等待 | 默认 300 秒 |
| 定时购买 | 5 位 cron，默认留空（不定时） |
| 使用代理 / 代理地址 | 留空地址则用 MoviePilot 的系统代理 |
| 页面超时 | 打开页面和等 Cloudflare 的最长时间 |
| 无头浏览器 | 默认关闭（Docker 里是虚拟显示），过 Cloudflare 更容易；起不来时自动改用无头 |
| 下单前清空购物车 | 默认开启，避免上次演练留下的商品混进本次订单 |
| 通知显示完整兑换码 | 关闭后只显示首尾 4 位，完整的码在插件详情页里 |
| 选择器覆盖 | 高级选项，见下文 |

## 安全设计

- 除了「立即购买一次」、命令和定时任务，插件不会自己下单。
- **从不自动重试付款**。付款后结果不明确时，状态记为「结果未知」，并提醒你去订单页核对。
- 下单前核对面额、价格、余额、应付金额（不能超过单笔上限，也不能明显高于「单价 × 数量」）。
- 截图会遮住卡信息输入框；保存的网页会抹掉输入框里的值和像卡号的长数字。
- 只取「最新一笔订单」里新出现的兑换码。买过的码会记下来，不会重复推送旧码。

## 选择器覆盖（页面结构和预期不同时）

在「选择器覆盖」里填一个 JSON 对象，键名如下。值可以是一个 CSS / Playwright 选择器，也可以是选择器数组：

| 键 | 用于 |
| --- | --- |
| `buy_now` `add_to_cart` `go_cart` `checkout` | 商品页的「Hemen Al / Sepete Ekle」、去购物车、去结算 |
| `pay_binance` `pay_balance` `pay_card` `pay_submit` `confirm_dialog` | 付款方式选项、最终付款按钮、确认对话框 |
| `saved_card` `card_number` `card_holder` `card_expiry` `card_month` `card_year` `card_cvv` | 已保存的卡、卡信息输入框 |
| `otp_input` `otp_submit` | 银行验证页的验证码输入框和提交按钮 |
| `binance_qr` | 币安付款二维码元素（自动识别不到时） |
| `reveal_code` `orders_link` `order_detail` | 「Kodu Göster」、我的订单、订单详情 |
| `login_link` `login_submit` `email_input` `password_input` `logged_in` | 登录相关；`logged_in` 填一个「已登录时才存在」的元素 |
| `price` `total` `balance` `quantity_input` `remove_item` | 价格、应付金额、余额、数量、购物车删除按钮 |
| `category_url` `cart_url` `orders_url` `login_url` | 分类页、购物车、订单页、登录页的地址（路径或完整网址） |
| `code_regex` | 兑换码的正则（有分组时取第 1 组） |

例：

```json
{"buy_now": "#btnHemenAl", "pay_balance": "label[for=odeme-bakiye]", "orders_url": "/hesabim/siparislerim"}
```

## 诊断文件

每次运行都会在插件数据目录的 `runs/<时间>/` 下保存每一步的截图（`.jpg`）、网页源码（`.html`）和步骤日志（`steps.log`），默认保留最近 10 次。
也可以直接下载最近一次的压缩包：

```
http://你的MoviePilot地址/api/v1/plugin/OyunforGiftCard/debug?apikey=你的APIKEY
```

**发给别人之前先自己看一遍**：网页里有你的用户名、余额和订单信息（卡号已经抹掉了）。

## 排查

| 现象 | 处理 |
| --- | --- |
| 需要登录 / Cookie 已失效 | 重新复制 Cookie；或者填账号密码让插件自己登录 |
| N 秒内未能通过 Cloudflare 质询 | 出口 IP 信誉差。换网络或代理，或者把「页面超时」调大 |
| 商品页没有找到「Hemen Al / Sepete Ekle」按钮 | 看截图：可能缺货、没登录，或者按钮文字不同（用 `buy_now` 覆盖） |
| 结算页没有找到「余额支付」选项 | 用 `pay_balance` 覆盖；有的站点要先充值才显示余额选项 |
| 商品价格和应付金额都没有识别出来 | 用 `price` 或 `total` 覆盖，或者把单笔上限设为 0（不推荐） |
| 付款成功，但没有自动找到兑换码 | 到 Oyunfor 订单页或邮箱查看；把诊断包发给帮你调试的人，用 `reveal_code` / `order_detail` / `code_regex` 调整 |
| 结果未知 | 插件已经点了付款，但没等到明确结果。**先去订单页核对，不要重复购买** |
| 收不到 3DS / 币安付款提醒 | 检查 MoviePilot 通知设置里是否开启了「插件」类型的消息 |
| 结算页没有找到「币安支付」选项 | 网站这时没有提供 Binance Pay（教程里提到有时不显示），或者选项文字不同（用 `pay_binance` 覆盖） |
| 提交后没有出现币安付款二维码或链接 | 看截图。二维码在别的位置的话，用 `binance_qr`（二维码元素的 CSS）覆盖 |
| 消息里没有二维码图片 | 有些渠道不支持插件图片。用消息里的付款链接，或打开插件详情页扫码 |

## 测试

`tests/oyunforgiftcard/` 是离线测试：在真实的 MoviePilot V2 后端里加载插件，用真实的 Chromium 访问本地模拟的
Oyunfor、支付网关（跨域 iframe）和银行 3DS 页面（短信 OTP 和 App 确认两种），覆盖演练、余额、银行卡、错误验证码、取消、超时、
账号密码加短信登录、各种限额和保护、远程命令、按钮回调、网页提交验证码、诊断包下载等场景。
币安支付有两种形态：二维码直接显示在 Oyunfor 页面上，或跳转到币安托管的收银台。测试覆盖了自动跳转、页面不跳转（靠订单页确认）、
付款选项本身就是按钮、超时、「已付款但没发货」、取消，以及「页脚的币安首页链接 / 币安 Logo 不能当成付款码」等陷阱。

```bash
export MP_HOST_DIR=/path/to/MoviePilot          # v2 分支源码，依赖与 app/helper 资源文件已就绪
export TEST_CHROMIUM=/path/to/chrome            # 本机 Chromium（CloakBrowser 测试也用它充当内核）
xvfb-run -a python -m pytest tests/oyunforgiftcard/test_helpers.py tests/oyunforgiftcard/test_flow.py tests/oyunforgiftcard/test_binance.py
xvfb-run -a python -m pytest tests/oyunforgiftcard/test_host_integration.py   # 需单独进程运行
```

模拟站点是臆造的，只能验证插件的流程和保护逻辑，不能代表真实站点。
