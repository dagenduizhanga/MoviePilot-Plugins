# Oyunfor 礼品卡购买

适用于 **MoviePilot V2** 的插件：在 [oyunfor.com](https://www.oyunfor.com) 自动购买 **App Store & iTunes 礼品卡（土耳其区，TL 面额）**，
取回兑换码后推送给你。

- **付款方式**：账户余额（默认）、币安支付（把付款码推给你）、银行卡（需要验证时推送给你）。选了银行卡或币安时，如果 Oyunfor 账户余额已经够付这一单，网站只给「用余额下单」，插件就直接用余额买（不刷卡、不用币安），通知里会写明。
- **验证提醒**：银行卡付款一律提醒「需要输入验证码」，你回复验证码即可；只需在 App 里点确认的（如 OKX），确认后页面会自动继续。
- **登录**：优先用 Cookie。Cookie 失效后用账号密码登录；Oyunfor 往你邮箱发验证码时，插件会推送提醒，你回复验证码即可。
- **安全**：账号、密码、Cookie、卡信息、登录状态、兑换码、运行截图，全部加密保存，详见下文。
- **默认开启演练模式**：只走到付款前一步，不扣款。购物车里的下一步按钮如果写着「Satın Al / Tamamla / Onayla」这类字样，并且会提交表单（可能直接下单），演练会停在那里，不会去点。

## 第一步：设置加密口令（必须）

插件**只用**环境变量 `OYUNFOR_SECRET` 里的口令来加密。没有设置这个口令时，插件不保存、也不使用任何账号信息。

1. 打开插件设置页，最上面会显示一个随机生成的口令。也可以自己生成，至少 16 位，越随机越好。
2. 把它加到 MoviePilot 的 docker 环境变量里，比如 docker-compose：

   ```yaml
   services:
     moviepilot:
       environment:
         - OYUNFOR_SECRET=这里填那串随机口令
   ```

3. 重启容器。

注意：

- **口令不要写进 `/config` 目录**（例如 `/config/app.env`）。它的作用就是和数据分开存放：数据库或备份被单独拿走，没有口令也解不开。
- **口令自己另存一份**（比如存在密码管理器里）。换了口令或口令丢了，已保存的内容就解不开，只能重新录入。

## 第二步：安全录入账号、Cookie、银行卡

插件设置页上有一个「**安全录入账号 / Cookie / 银行卡**」按钮。它打开一个一次性页面：10 分钟内有效，只能提交一次。在这里填：

- **Cookie**（推荐）：浏览器登录 oyunfor.com → F12 → 网络 → 任意请求 → 请求头里的 `Cookie` 整段复制。
- **账号 / 密码**（可选）：只在 Cookie 失效时用来登录。
- **银行卡**（只在付款方式选「银行卡」时需要）：卡号（会做校验位检查）、有效期、CVV、持卡人。

为什么不直接写在设置表单里？MoviePilot 保存设置时，会先把表单原样写进数据库。就算插件随后删掉，SQLite 文件里也可能残留旧数据。
安全录入页提交的内容会直接加密保存，从头到尾不以明文形式写进数据库或磁盘。

## 第三步：演练，再实买

1. 填面额（如 `250`）和数量，付款方式默认是「账户余额」。保持演练模式开启，打开「立即购买一次」，然后保存。
2. 一分钟后打开插件详情页，看结果和截图（截图是加密保存的，只在详情页里解密显示）。
3. 演练通过后关闭演练模式，先买一张最小面额的试试。

## 验证提醒长什么样

| 情况 | 消息标题 | 你要做的 |
| --- | --- | --- |
| 银行卡付款需要验证（3D Secure） | 【Oyunfor 付款验证】需要输入验证码 | 收到验证码后回复 `/oyunfor_code 123456`。只需在 App 里点确认的（如 OKX），确认后页面会自动继续，不用回复 |
| Cookie 失效、登录要验证码（通常发到邮箱） | 【Oyunfor 登录验证】需要验证码 | 回复 `/oyunfor_code 123456`。填错了插件会提示你重发，最多 3 次 |
| 不想买了 | — | `/oyunfor_cancel`，或点「❌ 取消购买」 |

验证码比验证页先到也没关系，插件会先存着，等输入框出现后自动填入。有的银行要先点「发送验证码」才会出现输入框，插件会替你点一次。
默认等 5 分钟，超时就放弃这笔交易。放弃之后，不要再在 App 里确认它。

> 插件的消息类型是「插件」。如果你在 MoviePilot 的通知设置里关掉了这个类型，就收不到验证提醒。

## 怎么挑商品

插件会打开 App Store 分类页（`https://www.oyunfor.com/apple-store/apple-store-itunes-gift-card`），
在商品卡片里找标题面额完全一致的那一张（`250` 不会选到 `2500`），然后点这张卡自己的 `SEPETE EKLE`。

如果没有这个面额，并且金额在 100 ~ 2000 之间，插件会用「100 - 2000 TL」那张卡，填入金额后加入购物车。
到了结算页，插件会核对应付金额是否约等于「单价 × 数量」：明显偏高或偏低都会停下，不付款。

## 远程命令

| 命令 | 说明 |
| --- | --- |
| `/oyunfor` | **最简单的买法**：只发 `/oyunfor` 弹出面额按钮（100 / 250 / 500 / 1000 … TL），点面额 → 选数量 → 点「购买」或「只演练」才开始（确认按钮 10 分钟内有效） |
| `/oyunfor 250` | 直接买 1 张 250 TL（不再确认）；`/oyunfor 375 2` 买 2 张 375 TL（100~2000 的任意整数）；末尾加 `dry` 只演练 |
| `/oyunfor_buy` | 和 `/oyunfor` 完全一样（旧写法） |
| `/oyunfor_code 123456` | 提交验证码（付款 / 登录）；不带参数表示「已在 App 里确认」 |
| `/oyunfor_paid` | 币安支付：告诉插件你已经付款 |
| `/oyunfor_cancel` | 取消正在进行的购买 |
| `/oyunfor_status` | 检查登录状态和余额 |

## 设置项

主界面只有这几项：启用、演练模式、立即购买一次、发送通知、面额、数量、付款方式。其余都收在「高级设置」里，一般不用改：

| 高级设置 | 说明 |
| --- | --- |
| 商品链接 | 默认就是 App Store 分类页（https://www.oyunfor.com/apple-store/apple-store-itunes-gift-card），一般不用改；也可以填单个商品页 |
| 单笔上限 / 每日最多下单 | 默认 2000 TL / 3 次（演练不计） |
| 定时购买 | cron 表达式，留空不定时 |
| 验证等待 / 币安付款等待 / 页面超时 | 默认 300 秒 / 15 分钟 / 60 秒 |
| 快速模式 | 默认开：点击之间的停顿缩短到约 30%；遇到网站拦截再关掉 |
| 快速下单 | 默认开：记住每个面额的商品编号，购买时直接加入购物车，不打开商品列表页；在机器人里点了面额就提前启动浏览器、打开并清空购物车，点「购买」时直接接着买（没点「购买」的话 3 分钟后自动关掉）；每天 04:10 刷新一次商品编号和登录状态。编号对不上会自动改回打开商品列表 |
| 代理、无头浏览器、下单前清空购物车、通知显示完整兑换码、保留运行记录 | 按需 |
| 选择器覆盖（JSON） | 页面结构和预期不同时使用，键名见文末 |

## 安全设计

| 内容 | 怎么保存 |
| --- | --- |
| 账号、密码、Cookie、卡号、有效期、CVV、持卡人 | AES-256-GCM 加密后存进插件数据，设置表里没有这些字段 |
| 浏览器登录状态（Cookie 等） | 加密文件 `session.enc`，读取时直接解密到内存交给浏览器，不落地明文 |
| 兑换码 | 历史记录里只存加密后的兑换码；查重只用不可逆的 HMAC 指纹。含兑换码的通知不写进 MoviePilot 的消息历史 |
| 每次运行的截图、网页、步骤日志、币安二维码 | 全部加密文件（`.enc`）。截图里的卡信息输入框和兑换码都会遮挡；网页源码先去掉输入框的值、卡号样的长数字和兑换码，再加密 |
| 日志 | 不记录任何账号、卡信息或兑换码；账号在步骤记录里也打码 |

**密钥：**

- 口令只来自环境变量，经 scrypt（N=2^16，约 64 MB 内存）派生出 256 位主密钥；不同用途再用 HKDF 分出子密钥。
- 每次加密都用新的随机 nonce，所以同样的内容两次加密，结果也不一样。
- 密文和用途、插件 ID 绑定：被改动一位、被挪作他用都会解密失败。

**安全录入页：**

- 一次性令牌，256 位，10 分钟过期，只能提交一次。
- 页面禁止缓存、禁止被嵌入，带严格的 CSP。
- 回显内容只有打码后的提示。

**怎么测的（`tests/oyunforgiftcard/test_security.py`）：**

- 跑一遍完整的银行卡购买（填卡、3DS 验证码、取码）后，逐字节扫描整个配置目录（MoviePilot 数据库、日志、插件数据），
  搜卡号（含空格版、base64 版）、CVV、密码、Cookie、账号、持卡人、兑换码和口令本身，结果都为零。
- 攻击者拿到整个配置目录但没有口令：解不开。用错口令、用常见口令去猜：解不开，而且每猜一次要约 160 ms。
- 密文改动一位就解密失败；口令太短（少于 16 位）插件直接拒绝使用。

**上限（实话实说）：**

- 插件要无人值守地登录、付款，就必须能解密。能控制运行中的容器（拿到环境变量或内存）的人，理论上也能拿到明文。
  所有自动化方案都有这个上限。
- 局域网里用 http 打开安全录入页时，提交的内容是明文传输的。从外网访问请给 MoviePilot 配置 https。
- 建议用限额低的卡或虚拟卡，Oyunfor 密码不要和别处共用。

## 诊断

每次运行的截图和网页都加密保存在插件数据目录的 `runs/` 下，默认保留最近 10 次。最近一次截图会显示在插件详情页。
要发给别人排查时，可以下载解密后的压缩包：

```
http://你的MoviePilot地址/api/v1/plugin/OyunforGiftCard/debug?apikey=你的APIKEY
```

压缩包是解密后的，里面有你的用户名和余额，发之前先自己看一遍。卡信息和兑换码已经遮挡或去掉了。

| 现象 | 处理 |
| --- | --- |
| 设置页提示「还不能保存账号信息」 | 没有设置 `OYUNFOR_SECRET`，或者少于 16 位 |
| 解密失败：口令和加密时不一样 | 换过口令。重新打开「安全录入」填写 |
| 需要登录 / Cookie 已失效 | 在安全录入里更新 Cookie，或者填上账号密码 |
| N 秒内未能通过 Cloudflare 质询 | 出口 IP 信誉差。换网络或代理，或者调大页面超时 |
| 页面里没有 X TL 的商品 | 面额填错了，或者这个面额下架了。日志里会列出页面上有哪些商品 |
| 没有认出可以买的商品 / 没找到 Sepete Ekle 按钮 | 失败消息里会列出页面上看到的按钮。把这条消息（或插件详情页的截图）发给帮你调试的人，或者用 `add_to_cart` 选择器覆盖 |
| 支付页提示：…（hatali / reddedildi） | 卡被支付网关拒绝，或卡信息填错了 |
| 结果未知 | 插件已经点了付款，但没等到明确结果。**先去订单页核对，不要重复购买** |
| 收不到提醒 | 检查 MoviePilot 通知设置里是否开启了「插件」类型的消息 |

## 选择器覆盖（高级）

在「选择器覆盖」里填一个 JSON 对象，值可以是 CSS / Playwright 选择器，或选择器数组。可用的键：

| 用途 | 键 |
| --- | --- |
| 加购与结算 | `buy_now` `add_to_cart` `go_cart` `checkout` |
| 付款按钮 | `pay_balance` `pay_binance` `pay_card` `pay_submit` `confirm_dialog` |
| 银行卡与验证码 | `saved_card` `card_number` `card_holder` `card_expiry` `card_month` `card_year` `card_cvv` `otp_input` `otp_submit` |
| 币安与兑换码 | `binance_qr` `reveal_code` `orders_link` `order_detail` |
| 登录 | `login_link` `login_submit` `email_input` `password_input` `logged_in` |
| 读取数值与购物车 | `price` `total` `balance` `quantity_input` `remove_item` |
| 页面地址 | `category_url` `cart_url` `orders_url` `login_url` |
| 兑换码格式 | `code_regex` |

## 测试

`tests/oyunforgiftcard/` 是离线测试：在真实的 MoviePilot V2 后端里加载插件，用真实的 Chromium 访问本地模拟的 Oyunfor、
支付网关（跨域 iframe）、银行 3DS 页（验证码 / App 确认 / OKX 式纯 App 确认），以及登录邮箱验证码（单框 / 六格）。

```bash
export MP_HOST_DIR=/path/to/MoviePilot          # v2 分支源码，依赖与 app/helper 资源文件已就绪
export TEST_CHROMIUM=/path/to/chrome
xvfb-run -a python -m pytest tests/oyunforgiftcard/test_helpers.py tests/oyunforgiftcard/test_security.py \
    tests/oyunforgiftcard/test_flow.py tests/oyunforgiftcard/test_binance.py
xvfb-run -a python -m pytest tests/oyunforgiftcard/test_host_integration.py   # 需单独进程运行
```

模拟站点只能验证流程和保护逻辑。分类页是按真实截图做的，购物车、结算页、支付页是推断的。
